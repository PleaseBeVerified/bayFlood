# Bay Area Flood-Exposure Training Data Report

## Purpose

The app uses a trained flood-exposure model based on elevation, FEMA flood-zone
data, distance to Special Flood Hazard Area (SFHA) polygons, nearby mapped
water, and 100-year/24-hour rainfall. The training dataset creates the
model-ready table used by that classifier.

The first modeling target is whether a location resembles a place with a known
NFIP flood-insurance claim. This is a claim-like exposure signal, not a literal
annual probability that a specific property will flood.

## Current Dataset Summary

The current active training dataset contains **480 labeled locations**:

- **268** positive examples with `flooded = 1`
- **212** comparison examples with `flooded = 0`

The positive examples come from FEMA NFIP redacted claims data for Bay Area
counties. The comparison examples are generated or manually selected Bay Area
locations that are not known NFIP claim points in this dataset.

The full merged label file contained 291 rows before coverage filtering. Eleven
Solano County claim rows were excluded from the active dataset because their
rounded coordinates fall outside the installed elevation-raster coverage.
Those rows remain in `data/training-labels-outside-coverage.csv`. Additional
comparison samples were later added to improve class balance.

The dataset is suitable for testing the training workflow and a baseline model.
It should not yet be treated as a validated flood-probability dataset.

## Data Files

### `data/training-labels.csv`

This is the editable source-of-truth label file. Each row represents one
location and contains:

| Column | Meaning |
| --- | --- |
| `id` | Unique row identifier |
| `lat` | Latitude |
| `lng` | Longitude |
| `flooded` | Label: `1` for a known NFIP claim point, `0` for a comparison point |
| `source` | Label source, such as `nfip_claim` or `comparison_sample` |
| `flood_year` | Event year for a positive row, when known |
| `notes` | Human-readable context about the row |

The model learns from `flooded`, not from `flood_year` or `notes`. Flood year is
metadata for temporal auditing and future time-to-event modeling; using it as a
location feature would leak information that is unavailable for a new address.

### `data/training-table.csv`

This is the generated model-ready feature table. It is produced from
`training-labels.csv` by running:

```sh
npm run training:table
```

Do not edit this file by hand. Regenerate it after changing the label file.

### `data/training-labels-merged-unfiltered.csv`

Backup of the merged label set before filtering for installed app-data
coverage. It currently contains 291 data rows.

### `data/training-labels-outside-coverage.csv`

Labels excluded from the active table because the app could not sample
elevation for their coordinates. It currently contains 11 Solano County NFIP
claim rows.

## Labels

The target column is called `flooded`:

```text
1 = known NFIP flood-insurance claim point
0 = comparison point without a known NFIP claim label in this dataset
```

The positive labels come from FEMA's FIMA NFIP Redacted Claims data. NFIP
coordinates are privacy-protected and rounded, so they should not be treated as
exact parcel locations.

A `flooded = 0` label does not prove that a location has never flooded. It only
means that the location is being used as a comparison point because it is not a
known positive claim example in the current label set.

## Generated Features

The training table currently contains these app-derived fields:

| Column | Meaning |
| --- | --- |
| `elevation_m` | Sampled elevation in meters |
| `elevation_ft` | Sampled elevation in feet |
| `fema_zone` | FEMA flood zone sampled by the app |
| `fema_subtype` | FEMA zone subtype |
| `sfha` | `1` when the location is inside a Special Flood Hazard Area |
| `distance_sfha_m` | Distance to the nearest SFHA in meters |
| `rainfall_100yr_24h_in` | NOAA 100-year, 24-hour rainfall estimate in inches |
| `flood_year` | Known event year retained as non-feature metadata |
| `nearest_water_status` | Whether a nearby mapped water feature was found |
| `nearest_water_distance_m` | Distance to the nearest mapped water feature |
| `nearest_water_kind` | Type of nearby mapped water feature |
| `nearest_water_name` | Name of the nearest mapped water feature, when available |
The model uses one representation per physical signal and constrains elevation
and distance effects to be non-increasing, and rainfall and SFHA effects to be
non-decreasing.

The table also contains administrative or evaluation fields such as `id`,
`source`, `address`, `reference_score`, `reference_label`, `source_url`, and
`notes`. These should generally be excluded from model training. In particular,
`reference_score` and `reference_label` must not be used when evaluating a
model against an external benchmark because they can cause data leakage.

## Data Structure

The training pipeline has two stages:

```text
data/training-labels.csv
        |
        | npm run training:table
        v
data/training-table.csv
```

The label file stores the target label. The generated table joins those labels
with features from the existing flood-exposure data pipeline.

## Current Class Balance

The active dataset is now substantially more balanced than the original
prototype, but the comparison class is still smaller than the claim class:

```text
268 flooded = 1 rows
212 flooded = 0 rows
```

For a stronger baseline, add comparison points across the same counties,
elevation ranges, shoreline conditions, and distances from mapped floodplains.
Random comparison points alone may make the classification task unrealistically
easy.

## Known Data Issues

1. Several NFIP claims share the same rounded coordinate, especially around
   `38.5, -123`. This is a consequence of FEMA location redaction.

2. The NFIP claim flood zone may differ from the FEMA zone sampled by the app.
   The claim record describes its policy or claim context, while the app samples
   current local FEMA geometry at the rounded coordinate.

3. Comparison points are not verified non-flood locations.

4. Claim data reflects reported NFIP insurance claims, not every flood event.
   Locations without NFIP claims may be uninsured, outside the NFIP, or simply
   absent from the redacted dataset.

5. Eleven Solano County rows are outside the current elevation coverage and are
   excluded from the active table.

## Recommended Next Steps

1. Add more comparison points using geography- and elevation-matched sampling.
2. Expand elevation coverage so the excluded Solano County claims can be used.
3. Keep `training-labels.csv` as the editable source of truth.
4. Regenerate `training-table.csv` after every label or feature-pipeline change.
5. Keep grouped location splits so duplicate rounded coordinates cannot appear
   in both training and validation data; add broader county holdouts as the
   dataset grows.
6. Report precision, recall, ROC-AUC, Brier score, and confusion-matrix results
   rather than accuracy alone.
7. Compare the model against independent reference tools without importing
   those reference scores as training labels.

## Modeling Target

The first model should predict:

```text
flooded
```

where:

```text
1 = known NFIP claim point
0 = comparison sample
```

The result should be described as an estimate of claim-like flood exposure in
the training data. It should not be presented as the probability that a
particular Bay Area parcel will flood.

## Requirement For A Literal 100-Year Probability

The current rows are not sufficient for a literal future-horizon probability.
That target requires a known observation start and end for every property,
verified flood-event dates, and non-event properties known to have remained
under observation. With those fields, a survival or discrete-time hazard model
could estimate annual hazard and convert it to a 100-year cumulative
probability. Generated comparison points cannot supply the needed exposure
time.
